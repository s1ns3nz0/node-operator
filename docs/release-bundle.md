# Deterministic release bundle

`scripts/ci/build-release-bundle.sh OUTPUT_DIRECTORY` produces the local
release artifact for this repository. It makes no network, cloud, cluster,
registry, signing, vulnerability-scan, publishing, or deployment calls.

The output directory contains:

- `node-operator-release-bundle.tar`: deterministic POSIX tar archive with
  normalized mode, owner, group, and mtime;
- `node-operator-release-bundle.sha256`: its `sha256:<hex>` artifact digest;
- `manifest.json`: compact inventory of each bundled source/rendered file and
  its digest; and
- `sbom.cyclonedx.json`: a CycloneDX JSON SBOM generated by local Syft 1.42.4
  from the completed tar file; its metadata component version is the artifact
  digest. When Syft omits the optional `components` field for this
  manifest-only artifact, the builder adds an empty array without changing any
  existing component data; and
- `provenance-input.json`: unsigned, local provenance-shaped input for the
  existing release-evidence collector.

The archive includes the production source boundary only: `deploy/base`, both
Kustomize workload inputs and their rendered output, Terraform source/example
variables, and production Rego/data/schema files. Each source is materialized
from the recorded Git `HEAD`, then Kustomize renders from that snapshot; dirty
working-tree edits cannot mismatch the recorded `source_revision`. README
files, test fixtures, raw evidence, scanner reports, credentials, and
Kubernetes `Secret` objects are excluded. The builder fails if its staged input
contains a Kubernetes `Secret`, a PEM private key marker, or the repository's
raw-evidence test marker.

`provenance-input.json` is **not** a SLSA attestation and does not provide a
signature or verification result. A release workflow must obtain an actual
provenance attestation and signature verification record before giving them to
`collect-release-evidence.sh`; this file merely binds the locally built digest,
source revision, builder identifier, and deterministic bundle format for that
later workflow.

The SBOM command uses Syft's explicit `file:` source and disables its update
check. It does not pull images, enrich package data, sign anything, or run a
vulnerability scan. Its timestamp and serial number are tool-generated, so the
SBOM bytes are not expected to match across separate builds; the release tar
and its digest remain deterministic.

Run `scripts/ci/test-build-release-bundle.sh` to verify stable artifact bytes
across two builds, expected source/rendered paths, SBOM digest linkage, and the
non-sensitive artifact boundary.
